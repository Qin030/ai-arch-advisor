了解首次接觸建築流程的一般使用者，能否整理需求、提出問題、理解資訊，
並辨識仍需專業確認的事項。不驗證建築方案是否合法、工程報價是否正確。

## 2. 受測與預演分開

- 目標邀約 3–5 位無建築／室內設計／營建專業背景的成年使用者；這是計畫人數。
- 實際完成幾位就填幾位，不預填 `n=5`；開發者自行操作不計入受測樣本。
- 若仍使用固定摘要或假 API，可做「介面預演」，結果另存，不混入正式前後測。
- 正式前導測試前，主持人需確認當次部署的 commit、API／UI 版本、真實輸出、
  可用功能與已知缺陷。CI 綠燈本身不足以代表正式測試已就緒。
- 編修／匯出尚未完成時，可做明確縮限範圍的測試，但須事前記錄排除任務；
  不得事後刪除失敗任務以提高完成率，也不得宣稱全部 MVP 已驗收。
- 主持人先以同版本預演一次；同一輪受測期間不換版本或任務。
  緊急修正後另開一輪，保留原輪失敗紀錄，不直接合併分數。

每位受測者開始前的環境重置 SOP（預演資料也須隔離）：

1. 保存上一位的匿名紀錄，結束其操作；不要讓下一位看到上一位畫面。
2. 關閉本次測試的所有無痕視窗，再開新的無痕視窗連入同一部署，建立新的前端 session。
   不沿用舊分頁；清除瀏覽器快取不能代替 Streamlit session 重置。
3. 主持人確認開場輸入為空、沒有舊問題／摘要／待確認清單，再交給受測者。
   若仍有殘留，停止交接並排查，不開始計時；記錄重置方法與確認結果。
   此步驟不代表刪除了伺服器端歷史資料，原始資料仍依保存與刪除安排處理。

## 4. 主持開場與流程

以下時間為主持排程建議，不是完成門檻：說明與前測 5 分鐘、操作約 15 分鐘、
後測與訪談約 10 分鐘。受測者可休息或退出；超時照實記錄，不補成成功。

開場照讀：

> 今天測的是系統是否容易使用，不是在考你的建築知識。請使用我們提供的
> 虛構情境，不必提供自己的地址或家庭資料。你可以隨時跳過問題或停止。
> 請照自己的理解操作；若卡住可以告訴我。畫面內容是需求整理材料，涉及
> 法規、設計或工程的判定，仍需由專業人員確認。你的回饋不必正面。

先確認是否願意參與並記錄；錄音／錄影與匿名引用各自記錄同意狀態。
依序進行：背景題 → 前測四題 → 任務卡 → 後測四題 → 採用意願 → 訪談。
前測完成前不展示介面、不解釋「應該學會什麼」，後測前不公布任務答案。

### 主持協助規則

- 可重讀原任務、說「請照你的理解繼續」，不直接指出按鈕位置或答案。
- 若受測者主動求助或表示無法繼續，先記卡住位置，再詢問是否需要操作提示。
- 任何指定位置／步驟的提示或代操作都記「協助」，即使最後完成也不算獨立。
- 不將主動談論思路列為必要條件，避免干擾計時；可先操作、事後回顧。
- 系統失敗時記錯誤、畫面與任務，不替換成成功的假資料繼續計正式成果。
- 單人主持以同一時鐘記起訖及簡短事件筆記；徵得錄製同意後，可於測後回放補齊
  提示原話與卡住位置，標示哪些內容是回放補記。不同意錄製仍可參加，以現場筆記
  為準；來不及記或無法確認的細節標示缺漏，不憑印象補成精確時間或引言。

## 6. 給受測者的任務卡

主持人將以下情境及本輪納入的任務製成獨立紙本或置於獨立螢幕，避免操作時切換分頁。
前後測亦採事前選定的載具，題目與量尺相同；後測不展示前測答案。
不要把主持觀察表、完成條件或其他人的紀錄交給受測者。

虛構情境：你希望在臺南自地自建二層透天，家中預計三人同住，希望家裡
溫馨、動線方便，也想用手機控制智慧設備。你目前不知道基地地號與使用分區，
預算也還沒確認。其他偏好可自行選擇；不知道的項目可以留白或跳過。
以上人數與偏好僅是操作道具，不是法規、工程或統計事實。

1. 用自己的話開始規劃，完成畫面上的需求盤點。請不要為了填完而編造基地資料。
2. 查看盤點後的輸出，找出已記錄的需求及仍需確認的事項；指出其中一項要問誰。
3. 查看方案比較，說出一個差異與一項在選擇前仍要確認的資訊。
4. 找到某項資料的來源資訊，說明你能在哪裡看到發布機關、版本、適用地區與連結。
5. 若本輪包含編修匯出，刪除一項不想保留的摘要內容，標記一項重點並下載 Markdown
   或 PDF，開啟下載檔確認內容。只需操作本輪實際提供的匯出格式。

不得要求受測者推算建蔽率、容積率、合法樓地板面積或選出「正確」工程方案。

## 7. 任務分類、計時與逐人紀錄

任務狀態固定為 I 獨立完成、A 協助後完成、F 未完成、U 功能不可用、
E 事前排除、W 受測者退出。每項只能選一個，另寫原因；不要留模糊的「大致完成」。

中途退出時，正在執行的任務及後續尚未執行的「事前納入任務」均記 W，註明
「於 TX 進行中退出」或「完成 TX 後退出」及退出時間。已結束任務保留原狀態，
事前排除任務保留 E。未開始的 W 任務起訖記 NA，不填 0 秒；進行中的 W 記實際起訖。
例如 T2 途中退出且 T5 事前排除：T1 保留原紀錄，T2–T4 記 W，T5 保留 E。

計時：逐任務從主持人讀完任務、受測者表示準備好時開始，到符合完成條件或
停止時結束。初步摘要時間另計：從受測者第一次觸發送出開場敘述的操作起，
至第一次成功顯示兩份摘要與待確認清單。現有 UI 的操作是按下「開始整理需求」；
若部署版本改名，預演時須在第 3 節記下對應操作，同輪固定使用此單一起點。
不以開始打字作為另一種起點；初次提交前的閱讀與撰寫計入 T1，但不計入此摘要時間。
提交後的閱讀、輸入、等待、錯誤重試均計入，不因失敗或重試重新起算；排除前後測與訪談。
中途休息記時間與原因，保留原始經過時間；沒有成功產出則記 NA＋原因，
另記到停止為止的時間，不能填 0 秒。

## 8. 後測訪談

1. 哪個步驟最容易、哪個最難？可以指出剛才的畫面嗎？
2. 哪一題的提問理由有幫助，哪一題不清楚？
3. 畫面對你原意的整理，有哪裡相符或不相符？請舉例。
4. 你會把哪些內容當成已確認的資訊？哪些還會再找人確認？為什麼？
5. 如果現在要與建築師討論，你會先問什麼？
6. 你會如何使用或不使用這份摘要？還缺少什麼？

先記原話，再另欄寫觀察者解讀；不得把解讀改寫成受測者說過的引言。
不要問「這是不是讓你更有自主性」等預設正面效果的問題。

## 9. 結果整理規則（提案，定稿後才收資料）

- 報告本輪受邀、開始、完成、退出人數及版本；只填實際人數。
- 每題只比較同一人的有效前後測：後測減前測；報告逐人數值與該題有效配對數。
- 四題平均只使用四題前後測皆完整的受測者，先算逐人前／後平均再算差值，
  同時列有效人數。部分缺漏者仍可納入其完整單題分析，不補值。
- 任務獨立完成率＝狀態 I 次數／正式開始參與者的事前納入任務總次數。
  A/F/U/W 均不算 I；E 不入分母。另列每項任務的狀態分布及退出人數。
- 初步摘要時間只對成功產出的有效紀錄計平均，另列成功／開始人數、失敗、
  協助及休息狀況；不能只報成功者平均而隱藏失敗者。
- 摘要採用意願＝回答「願意」人數／實際看到摘要且回答願意、不願意或不確定者。
  不確定入分母；不回答不入分母但須另報數量；未看到摘要者另列。
- 小樣本同時報「幾人／幾人」或「幾次／幾次」，不能只報百分比。
- 不將主觀自評轉成正確性指標，不計算 Hit@5、拒答召回率或來源一致率；
  這些需要另有黃金標準或來源查證，不由一般使用者感覺判定。
- 企畫書的門檻是團隊自訂目標，不是成果。本文件不改其門檻，尚未實測一律
  寫「待實測」。正式比較門檻前，先確認本節分母與企畫書口徑一致。
- 沒有對照組，不宣稱因果效果或統計顯著；結論限於本輪小規模前導觀察。
