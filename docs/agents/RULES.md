# 團隊鐵律（所有 agent 共用）

> **這是唯一真相來源。** `CLAUDE.md` 以 `@` 匯入本檔；`AGENTS.md` 內嵌一份副本（改動時兩處同步）；Gemini 的 Gem 需手動更新。改這個檔案要兩人 approve。
>
> 修改本檔時必須同步 `AGENTS.md` 的內嵌副本，
> `tests/smoke/test_rules_sync.py` 會在 CI 檢查，新增規則時同時更新該測試的 RULE_MARKERS。

## 1. 產出者 ≠ 審查者
- 寫實作的 agent 不得撰寫該功能的測試。
- 寫測試的 agent，在測試合併前不得閱讀該功能的實作。
- 開 PR 的人不得 approve 自己的 PR。

## 2. Agent 不得合併
- Agent 可以 commit、可以開 PR、可以留 review comment。
- **merge 一律由人類執行，且必須是另一位成員。**

## 3. 不得捏造來源
- 法規條號、條文內容、統計數字、版本日期，一律只能來自人工提供的原始資料。
- 找不到原文時寫 `TODO: 待人工查證`，**不要填看起來合理的內容**。
- 這條若違反，整個作品的「可查核」立論就失效了。這是唯一一條違反即停工的規則。

## 4. 拒答是功能，不是失敗
- 資料不足時輸出「拒答 ＋ 待確認事項」是正確行為，不是要修的 bug。
- 不得為了讓回答看起來完整而推定、補值，或引用鄰近地區的規定。

## 5. 單一 PR diff 上限 400 行
- 超過就停下來，回報要如何拆成多個 PR，不要自己硬送。

## 6. 不得越界修改
- 只改與當前 issue 相關的檔案。
- 不得順手重構、改格式、升級依賴、修不相關的 lint 警告。

## 7. 功能凍結後（D8 起）
- 只接受 `fix:` 與 `docs:`。
- 收到新功能需求 → 拒絕，並回報「專案已進入功能凍結」。

## 8. 語言
- 程式碼識別字、commit message、PR 標題、log：英文。
- 使用者可見的輸出、文件、給人看的說明：繁體中文（臺灣用語）。

## 9. 不確定就停
- 規格不明、契約沒寫、與既有測試衝突、需要動到別人的目錄 → 停下來問人。
- 不要自己決定，然後在 PR 描述裡輕描淡寫帶過。
