description: 知識庫來源抽查，產出人工查證清單
---

對 `data/kb/` 執行來源抽查。

這是本專案風險最高的檢查。企畫書的整個立論建立在「每筆資料可追溯來源、版本與適用地區」，一筆捏造的條文就足以毀掉作品。

步驟：

1. 執行 `python scripts/validate_kb.py`，列出所有 metadata 不合規的切片
2. 隨機抽出 **30%** 的切片（至少 8 筆），對每一筆產出查證卡：

```
切片 ID：
標題：
宣稱來源：
宣稱版本日期：
適用地區：
content 前 50 字：
---
人工待確認：
  [ ] source_url 可開啟
  [ ] 該頁面確實含有 content 的文字
  [ ] version_date 與該頁面標示的修正/發布日期相符
  [ ] region 標示正確
```

3. 標記任何**可疑訊號**：
   - `content` 讀起來像摘要或改寫，而非法條原文的語氣
   - 條號格式不符該法規的慣例
   - `version_date` 是整數月初或年初（常見的捏造特徵）
   - 同一來源的多筆切片版本日期完全相同但條號跨度很大

4. 輸出 `docs/kb-audit-<日期>.md`

**你不負責判定真偽，你負責讓人工查證變得可執行。** 不要自己上網查證後宣稱「已確認正確」。
