---
description: 審查 M2 的 PR
---

審查 PR $ARGUMENTS。

用 `gh pr diff` 取得變更，然後逐項檢查：

**1. 契約一致性**
- 與 `docs/CONTRACT.md`、`schema/` 是否相符？
- 有沒有偷偷改了契約而沒有標記需要雙方 approve？

**2. 拒答行為**
- 這個變更有沒有讓任何一個「應拒答」的情境變成會回答？
- 有沒有引入 fallback 推定（查無 A 就用 B）？
- 拒答文案有沒有出現「可能」「一般而言」這類軟化措辭？

**3. 來源真實性**（若動到 `data/kb/`）
- 隨機抽 30% 切片，逐筆確認 `source_url` 能對應到 `content`
- **抽到任何一筆內容像是生成而非複製的，立刻停止審查並回報 M1**

**4. 規模與範圍**
- diff ≤ 400 行？
- 有沒有越界改到不相關的檔案？

**5. 測試**
- 新增功能有對應測試嗎？
- 測試是不是由寫實作的同一方產出的？（違反鐵律第 1 條）

輸出格式：逐項給「通過 / 有疑慮 / 不通過」，有疑慮或不通過的要指出具體行號。

**最後不要 approve，也不要 merge。** 把結論交給 M1，由 M1 人工決定。
